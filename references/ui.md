# UI: injecting into game widgets, windows, popups, lists

Part of the `satisfactory-modding` skill. Markers: no marker = verified in practice, **[source]** = read from SML or game code, not tested, **[?]** = uncertain. Replace the parts in `<...>` with your own.

**Injecting UI into game widgets from C++**
- `Cast<UWidgetBlueprintGeneratedClass>(Cls)->GetWidgetTreeArchetype()`, `FindWidget("...")`, `InsertChildAt`, `ConstructWidget`, copy the `UCanvasPanelSlot` layout.
- Guards: `RequiresCookedData()`, `FPlatformProperties::IsServerOnly()`, `FApp::CanEverRender()`, `IsNetMode(NM_Client)`.
- SML widget hooks do the same without touching the tree by hand, and work entirely from C++ (`references/sml-api.md`, "SML: hooks"). Verified on the station, signal and locomotive windows (2026-10-02, game 502094, SML 3.12.0).
- **Checking a widget hook:** right after `RegisterWidgetBlueprintHook` the widget is already in the window class archetype (`GetWidgetTreeArchetype()->FindWidget(NewWidgetName)`), so this lookup is a start-up check that the hook got in. **[?]** The failing case (a parent panel that no longer exists) was not provoked; SML is expected to log its own error then.
- **[source]** Widget hook registration returns at once on a dedicated server and silently when `FSatisfactoryModLoader::IsAssetHookingAllowed()` is false (`WidgetBlueprintHookManager.cpp:227-233`, SML 3.12.0). A start-up check that looks for the hooked widget in the archetype then finds nothing although the window is unchanged; skip the check in those two cases instead of logging an error. (2026-10-04, SML 3.12.0)
- **A C++ widget without an asset:** a plain `UUserWidget` subclass builds its tree in `RebuildWidget()`: create `WidgetTree` if it is null, set `WidgetTree->RootWidget` once (`WidgetTree->ConstructWidget<UCheckBox>(...)` and so on), then call `Super::RebuildWidget()`. Inside a hooked window, `GetTypedOuter<UFGInteractWidget>()` returns the owning window, also through named slots.
- **Order of construction:** the hooked child's `NativeConstruct` runs before the window's own Blueprint `Construct`. Variables the window sets there (for example `mTrain` of the locomotive window) are read a tick later (`SetTimerForNextTick`) or when used.
- **A new window on every open:** `AFGHUD::OpenInteractUI` created a new window instance each time, so nothing carries over between objects, and the widget remembers nothing either. Read the shown state from the mod when the widget is constructed.
- **Do not change the widget's slot in `NativeConstruct`.** `UVerticalBoxSlot::SetSize` there crashed with `Assertion failed: WidgetPtr` in `TWidgetSlotWithAttributeSupport<…>::GetContainerWidget`, because `NativeConstruct` runs inside the parent's `BuildSlot` → `TakeWidget`, before the Slate slot holds the widget. Set slot properties on the class archetype once, right after registering the hook: `GetWidgetTreeArchetype()->FindWidget(NewWidgetName)->Slot`. Every window created later copies them. Example: `Fill` size with bottom alignment puts a row at the bottom of a column. (2026-10-03, game 502094, SML 3.12.0)
- **Text colour:** the first `UTextBlock` of a game window is often a dim label. Borrow the font from a game text, but set the colour yourself.
- `UComboBoxString::InitFont` and `InitForegroundColor` are `protected` in UE 5.6 (error C2248 from outside the class). The public `Font` and `ForegroundColor` fields are deprecated since 5.2 but still assignable; they are read only when the Slate widget is built, so set them right after `ConstructWidget` inside `PRAGMA_DISABLE_DEPRECATION_WARNINGS` / `PRAGMA_ENABLE_DEPRECATION_WARNINGS`. Style the rest with `SetWidgetStyle` (`ComboButtonStyle.ButtonStyle`, `MenuBorderBrush`) and `SetItemStyle` (`FTableRowStyle` row and selection brushes, text colours). A list built this way inside a game window showed the game's font and the chosen colours. Evidence: compile error, then screenshots of the packaged game. (2026-10-03, game 502094, SML 3.12.0, UE 5.6.1-CSS)
- **A searchable drop-down built from UMG parts** (the engine's `UComboBoxString` cannot narrow its options while typing): a `UButton` field (label plus a `UImage` with the combo style's `ComboButtonStyle.DownArrowImage`), and a `UScrollBox` of `UButton` rows on a `UOverlay` layer above the content, placed under the field from cached geometry (`ContentGeometry.AbsoluteToLocal(FieldGeometry.LocalToAbsolute(FVector2D(0, FieldSize.Y)))` as the overlay slot's padding, width = the field's local width). Make the owning `UUserWidget` focusable (`SetIsFocusable(true)`), call `SetKeyboardFocus()` when the list opens, and handle `NativeOnKeyChar` for the letters and `NativeOnKeyDown` for Enter, Backspace and Escape; return `Handled` for keys that carry a character while the list is open, so the game window's own keys (E closes it) do not fire. Typed letters reached the widget in a game window and narrowed the list (`'ir'` left 5 of 174 cargo names). Evidence: screenshots by the player, log `Cargo list: typed 'ir', 5 matches`. (2026-10-04, game 502094, SML 3.12.0, UE 5.6.1-CSS)
  - Traps seen on the way:
    - a `UOverlaySlot` aligns its child left by default, so the main column shrank to its content until set to `HAlign_Fill`,
    - a `UScrollBox` without a background lets the widgets below show through beside its scroll bar,
    - a scrolled `UScrollBox` draws a top shadow (`FScrollBoxStyle` `TopShadowBrush`) that made the list look a level below its field until set to `FSlateNoResource()`,
    - a `UButton` row keeps the `UButtonSlot` padding, so rows were taller than the game's drop-down rows until that padding was set.
- **Traps of a searchable list in a window tab.** With `NativeOnKeyChar` returning `Handled`, an open list kept the keyboard when the player clicked empty space in the tab (the tab keeps the focus) and swallowed every letter, the window's close key included. Close the list in `NativeOnRemovedFromFocusPath`, on a tab switch and on a mouse-down outside it; after that change a click beside the list closed it and the close key closed the window. **[?]** `UButton::OnClicked` has no row argument; picking the row by `HasAnyUserFocus()` first and `IsHovered()` second worked in the log, the order was only reviewed. (2026-10-04, game 502094, SML 3.12.0)
- **Rebuilding a list inside its own event.** A combo box's `OnSelectionChanged` handler that clears and refills the options of that same box is a re-entrancy risk; redraw in the next frame (`SetTimerForNextTick`) instead. **[source]** `UComboBoxString::ClearOptions` calls `ClearSelection`, which clears the Slate list's selection, and when something was selected `HandleSelectionChanged` broadcasts `OnSelectionChanged` with an empty string (`ComboBoxString.cpp:185-210, 464-479`, `SComboBox.h:358`). A handler that forwards the value to the server then wipes it. Rebuild under a guard flag and ignore an empty option. (2026-10-04, UE 5.6.1-CSS)
- **Opening a window from C++:** `AFGHUD::OpenInteractUI(WidgetClass, Object)` opens any interaction window. It lands on `UFGGameUI::GetInteractWidgetStack()`, and `UFGGameUI::PopWidget` closes it. `AFGBuildable::GetInteractWidgetClass()` is protected, so read `mInteractWidgetSoftClass` through reflection.
  - **[?]** The same call a few frames after a save had loaded crashed in `UE::MovieScene::FSequenceInstance::Start()` (null read, from `UUMGSequenceTickManager::TickWidgetAnimations`). 15 s later it worked in every following run. One crash, cause not proven: let the world settle first. A later finding partly explains it: right after a load the game can sit in one long frame (see "A test that waits on the core ticker" in `references/testing.md`).
  - **[?]** A widget class loaded with `LoadSynchronous()` and kept only in a plain `TSubclassOf` in a non-UPROPERTY struct was unusable 15 s later. Keeping it in `TStrongObjectPtr<UClass>` fixed it. Whether the class or the target object went invalid was not logged.
- **The game's popup with a C++ content widget.** `UFGBlueprintFunctionLibrary::AddPopupWithContent(Controller, Title, Body, CloseDelegate, Content, EKeys::Invalid, PID_OK)` with a plain C++ subclass of `UFGPopupWidgetContent` (tree built in `RebuildWidget`) shows the popup (`Widget_Popup_C`) with the title and the content, but **not the Body text, and its Confirm button stays greyed**, so the player cannot close it. The popup asks the content `GetShouldOkayBeEnabled` (a `BlueprintImplementableEvent`) from Blueprint, which returns false without a Blueprint implementation; overriding `UObject::ProcessEvent` in the content does not catch that call.
  - What works: queue it with `PID_NONE` (no buttons) and an empty body, put the text and an own OK button into the content, and from that button call `mPopupWidget->CallPopupClosedClicked(true)` (`mPopupWidget` is set by the game), which fires the `FPopupClosed` delegate (`BindUFunction` on the content) with `true`, and then `UFGBlueprintFunctionLibrary::ClosePopup(PlayerController)`. A `PID_NONE` popup does not take itself off the screen after `CallPopupClosedClicked` (a player's click logged the delegate ten times while the popup stayed); `ClosePopup` removes it and `HasActivePopup` is false afterwards. Guard the delegate handler against running twice.
  - The engine's default `UCheckBox` images (with the tick) can be tinted through `FCheckBoxStyle` brushes' `TintColor`; replacing them with plain rounded brushes loses the tick. The popup then spans the screen width as a dark bar.
  - Evidence: screenshots of both variants; log `Inactive warning closed (OK 1), do not show again 1`; test check `the popup is gone after OK`; the player's clicks. (2026-10-04, game 502094, SML 3.12.0, UE 5.6.1-CSS)
- **Finding a hooked widget's window in a test.** The game's interact windows (locomotive window at least) are not `IsInViewport()`; they sit in a panel of the game UI. Look up the window as the widget's `GetTypedOuter<UFGInteractWidget>()` with `GetParent() != nullptr` (a closed window has left its panel). Evidence: lookup by `IsInViewport` found nothing, lookup by parent found the switch in every run. (2026-10-04, game 502094, SML 3.12.0)
- **Reading a game window's real structure:** the starter project has only stubs, so dump it in the packaged game. Archetype tree: `GetWidgetTreeArchetype()->RootWidget` walked through `UPanelWidget::GetChildAt`. Named slot content: `UUserWidget::GetSlotNames` + `GetContentForSlot`. Blueprint variables and functions: `TFieldIterator<FProperty>` and `TFieldIterator<UFunction>` with `EFieldIterationFlags::None` for each Blueprint class in the chain. Live tree: open the window with `OpenInteractUI` and walk `WidgetTree` of each nested `UUserWidget`.
- A row of a long list inside a `UScrollBox` that was scrolled out of sight keeps the `GetCachedGeometry()` of its last paint: Slate does not paint culled children (`SPanel` paint skips them), so testing "is this row on screen" by intersecting the row's cached rectangle with the scroll box's one still says yes for every row that was ever seen. Works: override `NativePaint` in the row's `UUserWidget`, store `GFrameCounter` in a `mutable` member, call `Super`, and treat the row as on screen when that frame is at most 2 frames old (`SObjectWidget::OnPaint` calls `NativePaint` on every paint, also without a Blueprint `OnPaint`). Evidence: a list of 305 rows, scrolled down and back to the top: 0 rows counted as on screen with the paint stamp, while the rectangle test counted the rows seen before; at the end 19 of 305 on screen. Measured 2026-10-13, UE 5.6.1-CSS, game CL 513885, SML 3.12.0.
- Bold section headings in a C++-built tab: take the game's font from a text in the host window, then set `FSlateFontInfo::TypefaceFontName` to a face of its composite font named `Bold` (look it up in `GetCompositeFont()->DefaultTypeface.Fonts`, keep the font unchanged when no such face exists). The game's UI font has a `Bold` face; checked on a screenshot of the station window, 2026-10-13, game CL 513885.
- `UPanelWidget::ShiftChild(Index, Child)` reorders only the UMG `Slots` array and calls `InvalidateLayoutAndVolatility()`; the live `SVerticalBox` keeps its old order, so a list "sorted" with `ShiftChild` after its Slate widget exists does not move on screen, and a test that reads `GetAllChildren()` (UMG order) passes anyway. Re-adding the slots in Slate (`Shown->ClearChildren()` then `UVerticalBoxSlot::BuildSlot(Shown)` for each slot) moves them but cost 34.85 ms for 305 rows; `ClearChildren()` + `AddChild` in UMG cost 39 ms. Cheapest: keep the row widgets where they are and give each row the item it should show in the new order (set the data, refresh the row): 0.81 ms for 305 rows. A test of on-screen order reads the Slate children (`Box->GetCachedWidget()->GetChildren()`, matched to rows by `GetCachedWidget()`). Evidence: `Engine/Source/Runtime/UMG/Private/Components/PanelWidget.cpp:200`, a <scenario> UI test with 305 table rows: sort 0.33 ms (UMG only, screen unchanged), 34.85 ms (Slate rebuild), 0.81 ms (data reassigned). (2026-10-21, game 513885, SML 3.12.0)
- Set a `UTextBlock`'s text only when it changed: every `SetText` lays the widget out again even with the same string. Refreshing 31 visible table rows of 5 cells each took 0.116 ms with `SetText` every time and 0.029 ms with the compare first. Evidence: a <scenario> UI test, same rows, same frame budget check. (2026-10-20, game 513885, SML 3.12.0)
- **A mod's own window in the game's look, from C++ only.** A plain C++ subclass of `UFGInteractWidget` opened with `AFGHUD::OpenInteractUI(UMyWindow::StaticClass(), Object)` sits in the interact stack like a building window (it replaced the open station window in the stack). The input defaults are set in its constructor (`mUseKeyboard`, `mUseMouse`, `mDisablePlayerActions`, `mDisableBuildGunActions`, `mSupportsStacking`, `mDesiredHorizontalAlignment/VerticalAlignment` centre). `RebuildWidget` builds the tree from the game's own Blueprint widgets, found with `FindFirstObject<UClass>(TEXT("Widget_Window_DarkMode_C"), EFindFirstObjectOptions::None)` (loaded once any game window was open; paths `/Game/FactoryGame/Interface/UI/Widget_Window_DarkMode`, `/Game/FactoryGame/Interface/UI/InGame/Widget_Window_ContentBackground_DarkMode`, `/Game/FactoryGame/Interface/UI/InGame/-Shared/Widget_StandardButton`): `WidgetTree->ConstructWidget<UUserWidget>(FrameClass)`, then by reflection right after construction `mTitleText` (FText) and `mShowCloseButton` (bool); the content goes into the frame's named slot `WindowBody` (`SetContentForSlot`), with a `Widget_Window_ContentBackground_DarkMode_C` behind it in an overlay. The frame's `OnClose` and the button's `OnClicked` are Blueprint multicast events without parameters: they are bound with `FMulticastDelegateProperty::AddDelegate` and a `FScriptDelegate` to a `UFUNCTION()`; the clicked button is the one whose inner `mButton` `IsHovered()`. A `Widget_StandardButton_C` takes its label from `mText` set before construction, and setting its bool `mIsOrangeButton` after construction does turn it orange (the selected section). In the packaged game: the frame with title and close button, the background and 6 bound buttons; the player confirmed the look matches the game's windows, the close button, Esc and the interact key closed it, the orange selection followed each click. Evidence: `frame /Game/FactoryGame/Interface/UI/Widget_Window_DarkMode.Widget_Window_DarkMode_C, buttons 6 (bound 6), close bound 1, missing []`, 23 logged section clicks, the player's verdict. For sizing: the locomotive window (`Widget_Locomotive_Menu_C`) is 1200 x 827 layout units, its content background 1200 x 700, the left column 300 wide. (2026-10-23, game 513885, SML 3.12.0)
- **A virtual list in C++ UMG: rebinding a row must not set its tooltip or brush again.** A table of hundreds of rows inside a `UScrollBox` stays cheap when only the rows in sight exist: a `USpacer` above and below (`SetSize(FVector2D(1, Lines * Height))`), a pool of row widgets in a `UVerticalBox` between them, every line one fixed height (row root `USizeBox::SetHeightOverride`), and each tick the first line in sight from `(ScrollBox abs Y - table abs Y) / scale`, read from the cached geometries. When the first line changes every row gets a new line. That rebinding cost about 35 µs a row (1.15 ms a frame for 32 rows) while the row called `SetToolTipText` and `UBorder::SetBrush` each time: `SetToolTipText` builds a new Slate tooltip widget. Setting both only when the row's kind or hover state changes brought the worst frame (a jump to the end and back) to 0.25 ms, and a sort of 1000 data items plus the rebind to 0.37 ms (1.03 ms before). The five `SetText` calls of a row are not the cost. Evidence: the test lines `the most a frame of the window took 1.146 ms` before and `0.246 ms` after, `a sort 1.03 ms` before and `0.37 ms` after, 1000 items in one group, the same save and laptop on turbo. (2026-10-23, game 513885, SML 3.12.0)
