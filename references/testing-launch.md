# Launch arguments and console options for test runs

Part of the `satisfactory-modding` skill. Markers: no marker = verified in practice, **[source]** = read from SML, game or engine code, not tested, **[?]** = uncertain. Replace the parts in `<...>` with your own. ## Settings files

- `-Multiprocess` stops the engine writing `GameUserSettings.ini`. Tested: the same save and launcher, window 800x600, `-Multiprocess` added: the file's hash was identical after the run (`hash before 5BE5FE351ED2 after 5BE5FE351ED2 changed: False`), while two runs without the flag rewrote it (`after 77447C1456DE changed: True`). Only that file was hashed, the rest of `Saved\Config\Windows` was not compared. **[source]** `AreWritesAllowedGlobally()` is false with `-Multiprocess` unless `-MultiprocessSaveConfig` is also given, and both ini writers check it (`<UE-CSS>/Engine/Source/Runtime/Core/Private/Misc/ConfigCacheIni.cpp:880-891, 2247`). SML's `Configs\<Mod>.cfg` files are JSON, not ini, so the switch does not cover them; keep the copy of those. The switch also skips the shader-directory cleanup (`LaunchEngineLoop.cpp:2857`). The docs use it only for a second local copy of the game, together with `-CustomConfig=` (which exists in the engine, `ConfigCacheIni.cpp:1287`; its effect in the game is **[?]**). (2026-10-24, game 513885, SML 3.12.0, docs.ficsit.app)

## Console commands from the command line

- `-ExecCmds="cmd1,cmd2 'arg,with,commas'"` works in Shipping through SML. Tested: `-ExecCmds="stat fps,<Mod>.Ping 42"` ran the mod's console command with its argument in the loaded game world (frame 1, after the save's load and the world module's `POST_INITIALIZATION`), not in the menu: `LogSatisfactoryModLoader: Display: Parsing ExecCmds` at engine init, `LogGame: World Serialization (load): 0.096 seconds`, then `Log<Mod>: Display: <TAG> PING args=[42] world=Persistent_Level`; `stat fps` leaves no log line. **[source]** A comma separates commands and single quotes protect commas inside an argument; the commands are queued to `GEngine->DeferredCommands` after engine initialisation (`SML/Private/SatisfactoryModLoader.cpp:222-229`; the parser is `<UE-CSS>/Engine/Source/Runtime/Engine/Private/ParseExecCommands.cpp:11-70`). The engine's own `-Exec=` and `-ExecCmds` run only when `!UE_BUILD_SHIPPING` (`UnrealEngine.cpp:2234`). It can replace test code that sets console variables, for example `-ExecCmds="FG.AutosaveInterval 0,t.MaxFPS 30"`. (2026-10-24, game 513885, SML 3.12.0, docs.ficsit.app)
- **[?]** Map options for the `LocalMapOptions` string beyond `skipOnboarding`, `listen` and `loadgame`. The docs list `?startloc=<PlayerStart tag>` (the hub is `TRADING_POST`), `?sessionName=`, `?DayLength=`, `?NightLength=`, `?allowPossessAny`, `?Visibility=SV_Private` and `?adminpassword=`, and say the page dates from 2021. A binary string search of the game's DLL found `allowPossessAny`, `startloc` and `DayLength` only as property names and no `adminpassword`, so none of them is confirmed. A custom level starts with `GameDefaultMap=/<Mod>/Maps/<L>/<L>.<L>` (docs). (2026-10-24, game 513885, SML 3.12.0, docs.ficsit.app)

## Console window and rendering

- **[?]** The docs say that selecting text in the plain `-log` console window freezes the game until Enter is pressed, so a stray click in an unattended, timed run could stall it. `-log -NewConsole` opens the Unreal Console instead, which does not freeze and adds filters, checkpoint markers and a command line (also for a dedicated server). The `-NewConsole` switch is read in `<UE-CSS>/Engine/Source/Runtime/ApplicationCore/Private/Windows/WindowsPlatformApplicationMisc.cpp:53` **[source]**; the freeze itself is from the docs only. (2026-10-24, game 513885, SML 3.12.0, docs.ficsit.app)
- `-RenderOffScreen` works on the game client, unlike `-nullrhi`, which killed it (`references/testing.md`, "The game client cannot run without a renderer"). Tested (640x480, all quality settings 0, 25 s in the world, one run each): it loaded the save, ran, exited cleanly (`LogExit: Exiting.`, exit code 0, no crash folder); dedicated VRAM of the process after 20 s max 1.25 GB, mean 1.19 GB (14 samples), against max 1.34 GB, mean 1.29 GB for the windowed run: about 0.1 GB (8 %) lower. It was not faster: 344 frames against 472 in the same 25 s (one run each, possibly noise), and the EOS overlay still creates its own D3D11 swap chain in both runs. **[source]** No swap chain is created for the game's own viewport (`WindowsD3D12Viewport.cpp:33`, `GenericWindow.cpp`) and the switch is honoured by the Windows application layer and Slate (`WindowsPlatformApplicationMisc.cpp:77`, `SlateApplication.cpp:857`). The docs use it with `-norhithread` for the asset dumper. **[?]** Screenshots from such a run are untested. (2026-10-24, game 513885, SML 3.12.0, docs.ficsit.app)
