# UI: key binds and texts

Part of the `satisfactory-modding` skill. Markers: no marker = verified in practice, **[source]** = read from SML or game code, not tested, **[?]** = uncertain. Replace the parts in `<...>` with your own.

## Key binds (Enhanced Input) for a mod
- **[source]** SML 3.12 has no key-bind registry. A mod's keys are Enhanced Input assets the game's own system reads (`UFGChildInputMappingContext`, `Input/FGChildInputMappingContext.h`). (2026-10-24, game 513885, SML 3.12.0)
- **[source]** A context asset must be a `UFGInputMappingContext` (`Input/FGInputMappingContext.h:22-28`), not the engine's class. Its menu category is `mDisplayName` and its sort order `mMenuPriority`. **[?]** The docs advise 200 or more to stay after the base game's entries. **[source]** A context that extends a vanilla one (`MC_PlayerController`, `MC_PlayerActions`, `MC_UserInterfaceBase`, `MC_Window`) is a `UFGChildInputMappingContext`, a primary data asset found through the Asset Manager, with `mParentContext` (`FGChildInputMappingContext.h:30`). It is found only when the mod's game feature data scans the `FGChildInputMappingContext` type on the folder `/<Mod>/Inputs`; Alpakit's wizard writes that rule (`references/mod-structure.md`). (2026-10-24, game 513885, SML 3.12.0, docs.ficsit.app)
- **[source]** Bind the actions in C++ from the static multicast `AFGCharacterPlayer::OnPlayerInputInitialized` (`(AFGCharacterPlayer*, UInputComponent*)`, `FGCharacterPlayer.h:45,1391`). Show the key to the player with `UFGInputLibrary::GetInputActionNameAsText(PlayerController, ActionName)` (`FGInputLibrary.h:84`); it returns UNKNOWN_KEY while the context is not bound. To bind a context by hand use `AFGPlayerController::SetMappingContextBoundWithHandle(FBoundMappingContextHandle&, Context, bBind, Priority, Owner)`, `BindMappingContext`, `BindDisabledMappingContext`, `UnbindMappingContext` or `UnbindAllMappingContextsByObject` (`FGPlayerController.h:731-760`), never the engine's `AddMappingContext`/`RemoveMappingContext`: they bypass the child contexts. (2026-10-24, game 513885, SML 3.12.0, docs.ficsit.app)
- docs.ficsit.app (Enhanced Input page) says the following; in game 513885 it is different:
  - **[source]** `AFGPlayerController::SetMappingContextBound` is gone, the header comment calls it "old" (`FGPlayerController.h:731-760`);
  - **[source]** the "Parent Context" field is not on `UFGInputMappingContext` but `mParentContext` on `UFGChildInputMappingContext`;
  - **[source]** `GetKeyNameForActionSimple` is not in the headers, `FGPlayerControllerBase::GetKeyNameForAction` is marked deprecated (`FGPlayerControllerBase.h:120`).
- **[?]** From the docs only: an actor that is not a character (a subsystem) needs `PC->EnableInput(Actor)` before it gets the input; a widget gets its contexts from `mInputMappingContexts` and `mInputGateDelayOpen` on the usable-widget base, which are Blueprint-side and not in the C++ headers; overriding `Destruct` without calling `Super` leaves the contexts bound; the console command `showdebug INPUT` works in the shipping game. (2026-10-24, game 513885, docs.ficsit.app)
- A `UTextBlock` with `SetAutoWrapText(true)` in a `UScrollBox` is measured with its real wrap only after it was painted, and a row out of view is not painted, so the box's content size and `GetScrollOffsetOfEnd()` grow while it scrolls and `ScrollToEnd()` stops short. `SetWrapTextAt(<fixed width>)` gives the right height before the first paint. Evidence: 40 two-line rows: `ScrollToEnd` reached offset 1012 of a then 1361 with the auto wrap, row 33 of 40 at the bottom; with a fixed wrap offset 1272 of 1272, the last row at the bottom. A widget out of view also keeps its last cached geometry: a row reported 0 wide until it was first painted. (2026-11-08, game 517554, SML 3.12.0)
- A test can scroll a list through the game's real input without touching the mouse: `FSlateApplication::Get().OnMouseWheel(Delta, Position)` with the middle of the list from `GetCachedGeometry().GetAbsolutePositionAtCoordinates(FVector2f(0.5f, 0.5f))`. Evidence: offset 0 to 96 after a delta of -3 in a popup, packaged game. (2026-11-08, game 517554, SML 3.12.0)
- A non-UFS file in a folder named in `Config/PluginSettings.ini` `+AdditionalNonUSFDirectories=` is read in the packaged game from `IPluginManager::Get().FindPlugin(<Mod>)->GetBaseDir() / <folder>/<file>` (`Projects` module); on the game it is a relative path, `../../../FactoryGame/Mods/GameFeatures/<Mod>/Resources/<file>`. Evidence: the file read in the packaged game, its log line with that path. (2026-11-08, game 517554, SML 3.12.0)

## Texts and localization
- **[?]** Text shown to the player is `FText`: `LOCTEXT` with `#define LOCTEXT_NAMESPACE` at the top of the .cpp and `#undef` at the end, or `NSLOCTEXT`. `FText::FromString` loses the localization key. A round trip FString to FText and back loses it too, so keep literals and do not convert; use `FName` for ids (docs, String Classes page). Text baked into a texture cannot be localized. (2026-10-24, game 513885, SML 3.12.0, docs.ficsit.app)
- **[source]** The CSS engine has a "Plugin Localization Target" (`Developer/Localization/Private/PluginLocalizationManager.cpp`). A plugin lists it in the `.uplugin`, as the example mod does: `"LocalizationTargets":[{"Name":"ExampleMod","LoadingPolicy":"Always","ConfigGenerationPolicy":"Never"}]`. **[?]** The target name must be unique across all mods (docs; use the mod reference). Staging the data is a modding edit in `CopyBuildToStagingDirectory` (`StageLocalizationDataForPlugin`). (2026-10-24, game 513885, docs.ficsit.app)
- **[?]** The docs call the system not fully ready (the compile, package and translation-service steps are TODO). Whether translations mount for a game feature mod is untested: the game feature state machine calls the explicit-plugin mount, which only logs a warning. (2026-10-24, game 513885, SML 3.12.0, docs.ficsit.app)
- **A popup content with a wrapping text spans the screen unless its width is capped.** In a C++ content widget for `AddPopupWithContent` (entry "The game's popup with a C++ content widget"), a `UTextBlock` with `SetAutoWrapText(true)` asks for the width of its whole unwrapped line, so with a text of about 330 characters the game's popup grew from the left to the right edge of the screen. A `USizeBox` around the content's column with `SetMaxDesiredWidth(640.f)` kept the popup at that width and the text wrapped into a few lines; short texts stay narrower. Evidence: the owner's in-game check of the popup before and after the change (the log line `Notice … shown` in both games). (2026-10-28, game 513885, SML 3.12.0)
- **A long setting name runs into its slider in the SML Mods menu.** In a vertical config section of float sliders (`UCP_Float`, `CPF_Slider`), the name column has a fixed width: a `DisplayName` of 41 characters ("Detour round a … (m)") ran its last 4 characters into the slider, while names of up to 36 characters did not. Evidence: the owner's screenshot of the Mods menu and the same menu after the name was cut to 35 characters. (2026-10-28, game 513885, SML 3.12.0)
