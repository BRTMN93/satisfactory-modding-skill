## references/testing-publishing.md

- **Announce a series of automated game runs with a table, then keep a counter.** Each run starts the game and takes minutes of the user's machine (GPU, power), so before the first run of a series show one table with the columns: number, run (scenario), save, what it checks that no other run does, state (waiting, running, PASS/FAIL) and time (estimated, then measured). Drop runs that only repeat what another run already proves. Before each later run give one line naming the run that starts; after each run one or two lines with "X of Y" and the result. Show the full table again when the series changes or the user asks. Every run, also inside a queue, has a watcher that reports its result at once, so a run that ended without a result (a closed game window) is noticed. Evidence: a user's working rules over several mod-testing sessions; the user asked for the table when it was missing. (2026-10-06, game 502094, SML 3.12.0)
- **A watcher that counts every tagged line as progress misses a run that stands still.** A scenario that prints a status table every 30 s while it waits kept `watch-run.sh` quiet for 20 minutes although nothing happened (the train it waited for was switched out of the mod's control in that save). `watch-run.sh` now takes `STATUS_PATTERN`, an extended regex of such status lines; they no longer count as a new step. Also give every scenario its own short limit for "nothing started yet" (e.g. fail when no job was sent after 3 minutes) and let the watcher report "no new step" after about 2 minutes, not 5. Evidence: a 21-minute stall with only status lines in the log; the pattern left 0 progress lines of 32 in the stalled window. (2026-10-06, game 502094, SML 3.12.0)
- **A queue of runs needs one watcher per run, too.** A single Haiku watcher told to watch a five-run queue (one script that runs the scenarios one after another) and to stop after 5 `RESULT` lines kept going after the queue ended: one run had no `RESULT` (its game was closed by hand after a deadlock), so the watcher was one short, took the next game (a manual test with the user, which never prints steps) for a run and reported a false 3-minute stall. This is the "two runs in one command" slip again. For a queue, start a fresh watcher whenever the queue script prints its line for a finished run (e.g. `QUEUE 04 PathWait exit 1`), or stop the watcher with `TaskStop` as soon as the queue prints its last line. Evidence: the false `STALL … (PlayerRoute test)` came 12 minutes after `QUEUE done`. (2026-10-06, game 502094, SML 3.12.0, Haiku 4.5)

## references/railroad.md

- **A heavier train accelerates more slowly, but the autopilot brakes it the same way.** This answers the **[source]** tutorial note on more than 4 wagons per locomotive. One locomotive with one Freight Car (330 t, 32 m) against one locomotive with seven Freight Cars (510 t, 128 m), both empty, two drives each on a double-track network, speed sampled every 0.1 s:

  | | L W, 330 t | L and 7 W, 510 t |
  |---|---|---|
  | 0 → 30 km/h | 1.6–2.6 s | 3.4 s |
  | 0 → 60 km/h | 3.2–4.2 s | 5.9 s |
  | 0 → 90 km/h | 5.2–6.5 s | 9.4–9.5 s |
  | 60 km/h → standstill at a station | 11.7 s over 54–57 m | 10.9–11.1 s over 44–48 m |

  The heavier train needs about 1.5 times as long to reach a speed. Braking for a station stop follows a fixed profile to the stop point, whatever the mass. So travel times learned for one consist do not carry over to another, and the difference comes from starting, not from stopping. Evidence: `drive 2 of 4: <name> <name> -> <name>, route 540.8 m, driven 540.4 m in 37.2 s, top 93 km/h; 0 to 30/60/90 km/h in 3.4/5.9/9.4 s; 60 km/h to standstill in 10.9 s over 44.3 m`. (2026-10-06, game 502094, SML 3.12.0)
- **`UFGRailroadVehicleMovementComponent::GetMass()` of a vehicle is its tare plus its cargo.** Summed over a train: a locomotive with one Freight Car 330 t empty, 400 t with 3200 iron ore in the wagon (70 t for 3200 ore). A locomotive with seven empty Freight Cars is 510 t, so a locomotive is 300 t and an empty Freight Car 30 t. Evidence: `mass 330.0 t` before loading and `mass 400.0 t loaded` after it, five deliveries in a row. (2026-10-06, game 502094, SML 3.12.0)
- **Travel times of the autopilot repeat to a tenth of a second.** The same train on the same free route took 35.5 s five times out of five (559.5 m, loaded) and 40.2–40.3 s four times (648.1 m, empty). A delivery of the same job took 102.8 s four times. So a time measured once already predicts the next drive, as long as no other train or signal holds it up. The first prediction, from the route length and a default 15 m/s, was 10% short. Evidence: `drove <name> -> <name> in 35.5 s, 559.5 m, 15.75 m/s, mass 400.0 t`, five lines. (2026-10-06, game 502094, SML 3.12.0)
- **A train that passes a station without stopping slows down through it.** A locomotive with one Freight Car on a one-way loop drove 53 km/h before a station it did not stop at, 47 km/h on the station's track and 82 km/h after it, the same on four passes. The cause (station track, curve or a signal at the station) was not checked. Evidence: `Train through <name> (pass 1): 53 km/h before, 47 entering, lowest 47, 82 leaving`, passes 2–4 identical. (2026-10-06, game 502094, SML 3.12.0)
- **A player's timetable route can be read leg by leg from the game's route search.** For each leg between two stops of a timetable, start the public route search (see "The game's route search can be run from any track connection") at the first stop's stop connection, as if the train were docked there. The tracks of the result's points (`Points[i]->GetTrack()`) are the tracks of the leg, and a point on a station's own track is a station the train passes without stopping. Compared with the tracks a train with the timetable B, A really drove, over four drives: 648.1 m read against 648.0–648.1 m driven, 559.5 m against 559.4 m, 32 tracks driven, 0 off the read route, 0 route tracks left undriven, and the station passed (`through <name>`) named. Read again when the timetable, the tracks (a graph generation) or the consist changes. Evidence: `drive 1, <name> to <name>, 648 m, through <name>: read 648.1 m, driven 648.0 m (-0.01%)`. (2026-10-06, game 502094, SML 3.12.0)
