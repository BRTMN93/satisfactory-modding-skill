# Railways: inserting a layout from code

Part of the `satisfactory-modding` skill, railroad domain (index: `domains/railroad/README.md`). Markers: no marker = verified in practice, **[source]** = read from SML or game code, not tested, **[?]** = uncertain. For tests that need a railway layout without building it by hand; the build list standard is in `domains/railroad/test-layouts.md`.

## Spawning tracks, stations, signals and trains without the build gun

- **A railway layout can be inserted from code without the build gun, and it behaves like a hand-built one.** With `AFGBuildableSubsystem::BeginSpawnBuildable(<class>, transform)` → setup → `FinishSpawning(transform)` for every piece, a straight line with two stations, freight platforms, block and path signals on both sides, Buffer Stops and a locomotive with a coupled freight car compared equal to the same layout built by hand in the game (the layout dump of both saves: same tracks, lengths, joints, blocks, signal types, sides and attachments, stations, platforms, train), and a train driven over both stopped at the same four signals within 0.0 m and docked at the far station. A loop with curves, two switches and a siding with 13 signals built the same way had every block valid. What each piece needs **before** `FinishSpawning` (its `BeginPlay` registers it with the railroad subsystem):
  - **Track:** `*Track->GetMutableSplinePointData() = { FSplinePointData(local start, tangent), FSplinePointData(local end, tangent) }` (straight: tangents of the length along it; a circular arc: Hermite tangents `4·tan(angle/4)·R`), then `Track->GetConnection(0 or 1)->AddConnection(<other end there>)` for each track end at that point whose outward normal faces this end (`AddConnection` sets both sides; a second one on the same end makes a switch). Connection 0 is the spline's start, 1 its end (0 cm off in every case).
  - **Station or platform:** its own track first (the class and spline from a station/platform already in the save, relative to its track end), then the building with `mRailroadTrack` set by reflection (`FindFProperty<FObjectPropertyBase>(Class, "mRailroadTrack")`; the header says the setup "needs to happen from the hologram and from begin play") and `mIsOrientationReversed` as wanted. After all of them, attach every pair of touching `UFGTrainPlatformConnection`s **both ways** (`AttachToConnection` on each side): left as spawned, the platform pointed at the station but the station at nothing, and a train never docked there (`not docked in 300 s`); attached both ways it docked. A station's name: `GetStationIdentifier()->SetStationName(...)` once the identifier exists (a tick or so after spawning).
  - **Signal:** the guarded end (the track end at the joint whose normal points the trains' way) into `mGuardedConnections`, the observed one (the next track's start) into `mObservedConnections` (both `UPROPERTY` arrays, written by reflection; `AddGuardedConnection` is private), `Guarded->SetFacingSignal(signal)`, `Observed->SetTrailingSignal(signal)`, `mIsLeftHanded` by reflection; position from a signal already in the save relative to its guarded end, mirrored across the track for the other side. The subsystem builds the blocks itself (`RBV_Valid`).
  - **Buffer Stop** (`AFGBuildableRailroadAttachment`): `GetConnection()->AddConnection(<free track end>)`.
  - **Vehicles:** `World->SpawnActorDeferred<AFGRailroadVehicle>(class, transform)`, `SetTrackPosition(FRailroadTrackPosition(track, offset, ±1))` (the sign from the track's direction at that offset against the wanted way), for the second and later ones `AFGRailroadSubsystem::CoupleTrains(<vehicle before>, <new one>)` ("may be a newly spawned unregistered vehicle"), then `FinishSpawning`: one train of two coupled vehicles.
  - **Switch control:** the class from the track hologram's `mDefaultSwitchControlRecipe` (read by reflection on the hologram CDO, `UFGBuildDescriptor::GetHologramClass`), `AddControlledConnection(<the end with two neighbours>)`, `<end>->SetSwitchControl(control)`.
  Evidence: <scenario> runs of 2026-10-25: comparison of the dumps `DIFF 0`, drive comparison `DRIVE DIFF 0` (stops 0.0 m, docked), negative controls (one signal on the other side, one left out) `DIFF 1` and `DIFF 8`; the loop: 1207 pieces, `0 differences`, 13 signals `RBV_Valid`, `switch controls placed: 2`. **[?]** A save made by such a test loads with 2 extra `LogSave: Error` lines per load about world objects (`BP_CreatureSpawner<n>`, `BP_Spline<n>` "contained inside of the World Partition Cell"), absent when the hand-built save of the same layout is loaded; cause not checked (the test's own save after teleporting the player around is suspected, not the layout). (2026-10-25, game 513885, SML 3.12.0)
- **A track spawned from code keeps an unrotated actor, with its way only in the spline points; a turned actor draws the far-away pieces turned twice.** `AFGBuildableRailroadTrack::GetActorLightweightInstanceData` gives one instance per mesh piece (`SM_TrainTrack_02`, about 8–10 m each) with `RelativeTransform` = piece start in actor space and a rotation taken from the spline's world-space direction, plus per-instance custom data from index 15 (world start, start tangent, world end, end tangent). Up close the material bends each piece from the custom data, so any actor rotation looks right. Past the instance's `MaxWPODistance` (`FInstanceData`, default 50000 cm) the piece is drawn unbent at `RelativeTransform` on top of the actor's rotation, so an actor turned by yaw θ draws every piece turned by θ again: tracks look like a row of cross pieces from far away and flicker while flying, though trains run normally. Tracks built with the hologram, including the tracks of stations and platforms, are saved with actor rotation `R(0)` and the spline points in world orientation. The fix is spawning at `FTransform(start)` and turning the points and tangents (`Frame.TransformVector`) into the spline instead of turning the actor.
  Evidence: <scenario> dump of 2026-10-25 printing actor rotation, spline points and the first two instances of every track: hand-built tracks `rot R(0)`, piece `rel` along world axes with a matching yaw; code-built tracks with actor yaw -90 had piece `rel` along local X but piece yaw -90 (90° off on screen, confirmed by the user flying over both). After the fix every code-built track dumps `rot R(0)`, pieces match the hand-built ones, the layout comparison stays `DIFF 0`, and the user reported the far view of hand-built tracks as correct. Game 1.x CL 513885, SML 3.12.0. The custom data layout and `MaxWPODistance` meaning are read from the dump and `AbstractInstance/Public/InstanceData.h` **[source]**; after the rebuild with unrotated track actors the user flew over the layout up close and from far away and confirmed the tracks look like hand-built ones (2026-10-25).
