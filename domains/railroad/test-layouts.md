# Railways: test layouts and build lists

Part of the `satisfactory-modding` skill, railroad domain (index: `domains/railroad/README.md`). The general rule is in `references/test-automation.md`. Markers: no marker = verified in practice, **[source]** = read from SML or game code, not tested, **[?]** = uncertain. Replace the parts in `<...>` with your own.

- **A mechanism checked on one track layout is not verified.** For a mechanism that depends on the tracks, list the popular layouts where it may behave differently (passing loop, siding, junction, two-way single track, dead end, station with several platforms), test those that fit in the session, build the rest from code where the mod's test harness can insert layouts (`domains/railroad/layouts-from-code.md`), give the user a build list only for what code cannot build, and write the rest into the backlog with the session that will check it.
- **Build test layouts from code, never through the build gun's hologram** (`domains/railroad/layouts-from-code.md`): the mod has a test harness that inserts them. Write the layout as a description in Foundations, insert it, check it against the description, then dump the signals and compare before any scenario. A build list for the user is only for:
  - layouts that test the game's build limits (ramps, the tightest curves, stacked tracks; insertion from code does not check them);
  - elements the code cannot insert (refused in the log, no shape to copy);
  - a request from the user.
  The user looks once in the game, up close and from far away, at every kind of element the code has not inserted before, because a data dump does not show drawing errors (tracks spawned with a turned actor looked turned 90 degrees from far away while every dump matched).
- **Build lists for test layouts** (and descriptions of layouts built from code). Give lengths and gaps in Foundations (one Foundation is 8 m) with positions along the line, not in metres, and add a schematic for every rebuild, drawn and written to the standard below. A small change such as one more signal needs no schematic. Use the game's English names for buildings and ports. Check the signals against the placement rules in `domains/railroad/signal-placement.md` instead of composing them from memory. After the build, first dump the signals from the save (type, direction, block error) and compare the dump with the list, and only then run the scenarios.

## Layout facts for build lists

- **The Railway build limits are fields of the track hologram, not the docs' numbers.** `AFGRailroadTrackHologram` (`Hologram/FGRailroadTrackHologram.h`: `mMinLength`, `mMaxLength`, `mMinBendRadius`, `mMaxGrade` in degrees, `mSnapDistance`), read by reflection from the class default object of `Holo_RailroadTrack_C` (the recipe descriptor's `UFGBuildDescriptor::GetHologramClass`). Game 513885: max grade 25°, min bend radius 15 m, max length 100 m per piece, snap distance 5 m; texts "Railroad Track is too steep!", "… turns too sharply!", "… is too long!", "… is too short!". So for build lists:
  - Ramps: Ramp 8 m x 1 m rises 7.1°, 8 m x 2 m 14.0° (both within), 8 m x 4 m 26.6° (too steep for track). Trains climb what a track can be built on (the docs' "nothing steeper than a 2 m ramp" is wrong): on humps of one Railway piece shaped as an S in the vertical, 14.0°, 20.6° and 24.2° at the steepest, the game's autopilot took an Electric Locomotive alone (300 t) and one with a Freight Car of 3200 iron ore (330 t) up every slope in 7.1–7.9 s, slowing only from about 20 to 18.3–19.6 m/s, 2 runs, 6 of 6 lanes. `UFGRailroadVehicleMovementComponent::GetTrackGrade` is a rise-over-run ratio, not degrees (0.24 / 0.36 / 0.42 there). Evidence: `<scenario> CLIMB <station>: 2 vehicles, 1 Freight Cars loaded with 3200 iron ore, mass 330 t, the top 9.6 m above the start` and the arrival at the top in both runs. Also loaded (3200 iron ore per car): a locomotive with 8 Freight Cars (540 t) on 24.2° over 4 Foundations, a locomotive with 4 cars on 20.6° over 8 and on 24.2° over 12 Foundations (28.8 m up), and that 4-car train (420 t) sent on from standstill a quarter of the way up the 12-Foundation slope: it rolled back 4.3 s, then pulled up and reached the top in 59.1 s. The full air brake did not hold that train on the slope (it slid back 15.6 s before it stood); **[?]** neither did an autopilot with an empty timetable (first try, log lost). Evidence: `<scenario> CLIMB <station> reached the top after 11.3 s at 13.5 m/s` (9 vehicles, 540 t). (2026-10-26, game 513885, SML 3.12.0)
  - Curves: a 90° curve in a 2x2 Foundation square (16 m radius) is within the 15 m limit; the docs' "smallest curve 3x3" is a player's rule. Such a curve inserted from code (one Railway piece, tightest radius 15.9 m) was driven through by the autopilot with a locomotive and a Freight Car without error: `<scenario> CURVE track ...: 25.1 m long, ends 16.0 m apart in x and 16.0 m in y, tightest radius 15.9 m` (2026-10-26, game 513885, SML 3.12.0). **[?]** Whether the track hologram builds it was not tried; its radius check would pass it.
  - Stacked rails: a track keeps one clearance box free, `CT_Soft`, 0–1 m above the rail and 2.4 m wide, so the game has no 12 m rule; the docs' three 4 m Foundations (12 m) is a margin for the train's height. From the mesh bounds, an Electric Locomotive reaches about 7.2 m above the rail (its light beam mesh 11.1 m, not a solid part) and a Freight Car 4.7 m (7.1 m with the cargo mesh), so a deck over a track needs about 7.2 m of free height: `<scenario> FOUNDATION BP_Locomotive_C meshes: ... SM_Locomotive_LOD4 -0.02..7.17 m above the rail` (2026-10-26, game 513885, SML 3.12.0). **[?]** Whether a Foundation hologram over a track is refused stays open: one spawned from code (`AFGHologram::SpawnHologramFromRecipe`, moved with `SetHologramLocationAndRotation`, asked with `ValidatePlacementAndCost`) never left `FGCDInitializing` and `FGCDInvalidAimLocation`, since it is not updated by the build gun.
  - Evidence: `<scenario> LIMITS Holo_RailroadTrack_C mMaxGrade = 25.00`, `mMinBendRadius = 1500.00`, `mMaxLength = 10000.00`, `ramp 8 m x 4 m: 26.57 degrees, max grade 25.00: too steep`, `track clearance (…): type CT_Soft, from 0.00 m to 1.00 m above the rail, 2.40 m wide`, `1 clearance boxes`. (2026-10-25, game 513885, SML 3.12.0)
- **Facts from the docs signal guide (docs.ficsit.app), tested (2026-10-26, game 513885, SML 3.12.0):** a block counts as occupied until the end of the train leaves it (it cleared with the tail 5.9 m short of the next signal and the front 42 m past it: `<scenario> TAIL t=19.2 block before <S2> left by the runner; its tail -5.91 m past <S2>, front 42.1 m past it`); trains look one block ahead and stop at the signal of the taken block, not one block earlier (front 2.00 m before it, `RSA_Stop`); the platform order must match the wagon order, and Empty Platforms fill the gaps (a locomotive with two Freight Cars at [Empty, Freight] loaded only the second car, at [Fluid Freight, Freight] the car beside the Fluid Freight Platform got nothing: `ore in the cars now: 0 3200`). Advice, not a game rule: 4x4 Foundation curves (a 2x2 curve is driven, above). The guide counts in normal Foundations (8 m x 8 m, as the build lists in this file); "4-meter foundation" there means a foundation 4 m high. (2026-10-24, game 513885, SML 3.12.0, docs.ficsit.app)
